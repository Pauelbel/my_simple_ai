# Установка и обновления

## Пакеты

- Windows 11 x64 — NSIS `currentUser` с автоматической установкой WebView2 при его отсутствии.
- Linux x86_64 — AppImage. Пользователь запускает файл из папки с правом записи, чтобы приложение могло заменить его при обновлении.
- Пакеты обеих платформ собирает GitHub Actions. Linux-раннер использует Ubuntu 22.04 как минимальную базу сборки.

## Проверка и установка обновления

1. Подписанный выпуск запрашивает `latest.json` по HTTPS при запуске и раз в четыре часа. Ручная проверка доступна в настройках.
2. Tauri сравнивает версии и показывает доступный выпуск. Манифест устанавливает отдельные адреса для `windows-x86_64` и `linux-x86_64`.
3. По нажатию «Обновить» приложение скачивает пакет и проверяет его подпись и версию. Во время скачивания можно продолжать редактировать заметки.
4. После загрузки появляется кнопка «Перезапустить для обновления». По нажатию приложение сохраняет актуальный Markdown, проверяет пакет и устанавливает его перед перезапуском. Если сохранение не удалось, пакет остаётся готовым к установке до закрытия приложения.
5. Ключ и URL обновлений отсутствуют в тестовой сборке. Проверка обновлений работает в подписанных выпусках NSIS и AppImage.

## Первый выпуск

Создайте ключ обновлений командой `npm run tauri -- signer generate --write-keys /путь/вне/репозитория/my-simple-ai.key` из `apps/desktop`. Храните ключ и пароль отдельно от Git.

В GitHub Actions настройте:

- Repository variable `TAURI_UPDATER_PUBLIC_KEY` — содержимое полученного файла `.pub`.
- Repository secret `TAURI_SIGNING_PRIVATE_KEY` — содержимое закрытого ключа.
- Repository secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль ключа.

Неподписанный Windows-установщик может вызывать предупреждение SmartScreen. Подпись обновлений Tauri проверяется приложением и используется независимо от сертификата издателя Windows.

## Следующий выпуск

1. Повышайте версию одновременно в `tauri.conf.json`, `Cargo.toml` и `package.json`, обновляя оба lock-файла.
2. Создайте и отправьте тег `vX.Y.Z` на проверенный коммит. Версия тега должна совпадать с `tauri.conf.json`.
3. Отправка тега автоматически запускает подписанную сборку в [Tauri packages](https://github.com/Pauelbel/my_simple_ai/actions/workflows/tauri-check.yml). Ручной запуск с тегом также доступен. При ручном запуске с пустым полем собираются тестовые пакеты.
4. После успешной сборки на обеих платформах workflow собирает манифест и публикует пакеты и их подписи единым релизом. Канал обновлений использует публично доступный `releases/latest/download/latest.json`.

Последующие выпуски должны подписываться тем же ключом. Для проверки полного цикла установите текущий выпуск под обычной учётной записью, выпустите следующую версию и примените обновление поверх первой.
